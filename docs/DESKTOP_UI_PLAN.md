# 桌面端界面重做计划

> 起因：桌面端功能齐了、验证也全绿，但**界面不像产品**。对照 `UIreferance/`
> 里的安卓端实机截图（本地参考，已在 `.gitignore` 里排除）能看出两类问题：
>
> 1. **信息架构与视觉语言**不像移动端：7 个平级入口、到处 1px 分隔线、
>    全站字阶压在 11–13px、图标是 unicode 字形、没有列表行/卡片/胶囊按钮
>    这类基本组件。
> 2. **界面里塞满了实现细节**：密钥环、明文存储、账号 UUID、后端 URL、
>    ZIP/SQLite 快照格式、`exportedAt=`、`Temp` 绝对路径、常驻的「就绪」状态栏。
>    这些是我当时**刻意**做的（在 `DESKTOP_PLAN.md` 里写成「不静默降级」的优点），
>    但位置错了：**该知道 ≠ 该在主流程里说**。
>
> 本文件是这两件事的施工图。功能逻辑（主进程 / IPC / DB / SQL）不动，
> 改动集中在前端的 `apps/desktop/src/renderer/**`。

---

## 0. 总原则

1. **不是重新设计，是把已有的设计系统接上。**
   `packages/design-tokens` 早就写好了完整的 MD3 亮/暗 24 个语义色、
   10 级字阶（`labelSmall 11` → `headlineSmall 24`）、8 级圆角、动效时长。
   而 `apps/desktop/src/renderer/style.css` 只手抄了**暗色 6 个变量**、
   圆角 4 个、字阶 **0 个**（`font-size:12px` 出现 28 次）。
   所以第一件事是**别再手抄**：改成构建期从令牌包生成。
2. **界面只说三件事**：用户能做什么、发生了什么、下一步做什么。
   实现细节（加密方式、格式、迁移、绝对路径）一律降到
   「设置 › 关于 › 诊断」。
3. **把规则变成机制。** 清一遍文案只解决今天；要有一条**黑名单断言**
   让「密钥环」「明文」「outbox」这类词再也进不来。
4. **每阶段可验证、可提交。** 沿用既有纪律：跑全量回归 + 更新探针 + 提交一次。

## 1. 移动端 vs 桌面端：差异清单

### 1.1 信息架构

|          | 安卓端                                                      | 桌面端（改造前）                                                         |
| -------- | ----------------------------------------------------------- | ------------------------------------------------------------------------ |
| 主框架   | 底部 3 tab：主页 / 音乐库 / 设置                            | 左栏 7 个平级入口 + 右栏 320px + 底部播放条 + **底部状态栏**             |
| 音乐库   | 页内 4 页签：播放列表 / 收藏夹 / 合集 / 分p                 | 拆成 6 个一级入口                                                        |
| 导入     | 音乐库页内的 `+` / 菜单                                     | **一级入口**                                                             |
| 设置     | **一级目的地**；9 个分类 → 子页                             | 右上角齿轮打开的**右侧抽屉**，4 个 tab 塞一屏                            |
| 账号     | 设置里**一行**：`BBPlayer 账号 · 御坂代理服务（@御坂鱼板）` | `key: value` 表：名称/用户名/**UUID**/**后端 URL**/登录时间/**加密说明** |
| 正在播放 | 独立 sheet：圆形大封面 + 封面取色模糊背景 + 队列            | 右栏里一个下划线 tab，「队列为空」                                       |

**结论**：移动端是「3 个目的地 → 页内页签 → 子页」，桌面端把**来源、视图、
动作**混在同一级。→ 阶段 2 对齐。

### 1.2 视觉语言

| 维度   | 安卓端                   | 桌面端（改造前）                   | 证据                                              |
| ------ | ------------------------ | ---------------------------------- | ------------------------------------------------- |
| 配色   | MD3 亮色为主 + 动态主题  | 只有 `dark`/`light`，默认 dark     | `settings.cjs:25`                                 |
| 令牌   | ——                       | **包里全有，界面基本没用**         | `style.css:5-35` 只抄了 6 个暗色变量              |
| 字阶   | 标题 22–24 / 正文 14–16  | 全站 11–13px                       | `font-size:12px`×28、`11px`×4、`13px`×7、`14px`×2 |
| 圆角   | 卡片 24 / 按钮 28 / 胶囊 | 最大 16，大量直角面板              | `style.css:17-20`                                 |
| 图标   | 统一 Material 图标       | unicode 字形（♪ ▾ ⌕ ↧ ⟳ ★ ☰ ⇄ ⚙） | 全工程**无** `woff2/ttf/svg` 资产                 |
| 分隔   | 靠留白与字重             | 到处 1px `border`                  | `style.css:72/89`、`.playbar`、`.status-bar`      |
| 选中态 | 胶囊高亮                 | 下划线 tab（IDE 惯用法）           | 右栏页签                                          |
| 强调色 | 跟随主题                 | 硬编码 `rgba(208,188,255,.16)`     | `.nav__item.is-active`                            |

**「杂乱」的根因不是配色**（配色本来就是对的 MD3 暗色），而是
**没有组件词汇表**：没有「列表行 / 卡片 / 胶囊按钮 / 开关 / 浮动标签输入框 /
空状态」，于是每个面板都在用「`<h3>` + 一行说明 + 一排等权重灰按钮 +
平铺表单」临时拼。

### 1.3 参考设计：Salt Player 有什么值得抄

> 依据：Salt Player `12.0.0` 的发布说明（[newreleases.io 上的原文](https://newreleases.io/project/github/Moriafly/SaltPlayerSource/release/12.0.0)）。
> 我**没有**看过它的界面截图，所以下面只写 release notes 里明确提到的机制，
> 不凭印象编造视觉细节。想更贴近的话，把 Salt Player 的截图也丢进
> `UIreferance/` 我再对着做。

| Salt Player 的做法                                                                             | 它的价值                                                       | 我要落到哪                                                                |
| ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **「材质」设置页**：标题栏背景可选 _无效果 / 遮罩模糊（Android 12+）/ 渐变模糊（Android 13+）_ | 让用户自己决定"要多通透"；模糊是当下音乐播放器最好用的质感手段 | 阶段 1 建 `backdrop-filter` 材质层 + 三档强度；阶段 4 在「外观」里开出来  |
| **动态流光效果** + 「播放界面浅色流光下的前景色取色」                                          | 强调色驱动的动态光影，且**前景色跟着取色走**保证可读性         | 阶段 4：由系统主题色/自定义色驱动的一组缓慢流动的渐变，并对比度校验前景色 |
| **迷你播放条支持逐字歌词**                                                                     | 把"歌词"这个 BBPlayer 的强项塞进最小的一处空间                 | 阶段 2：悬浮播放条上跑逐字歌词（splash 已经能解析，桌面端已有歌词数据）   |
| **设置 → 用户界面 → 材质** 这种"设置里的设置"层级                                              | 高级项不污染一级菜单                                           | 阶段 3 的分类 → 子页结构                                                  |
| **歌词交错滚动** 放在「实验室」                                                                | 实验性效果与稳定功能分开                                       | 阶段 4：把实验性视觉效果收进「外观 › 实验室」                             |
| 无歌词时的专用组件样式                                                                         | 空状态是被认真设计过的，不是留白                               | 阶段 1 的空状态组件                                                       |

### 1.4 必须保留的 BBPlayer 自己的特色

改造是"换壳 + 接设计系统"，**不是**把 BBPlayer 做成 Salt Player 的仿制品。
下面这些是它在截图里一眼可辨的身份，改造中不能丢：

1. **彩虹渐变的「首字」方块头像**（`默认收藏夹` 的「默」、`星尘` 的「星」…）——
   收藏夹没有封面，用首字 + 渐变底色是最省事又最好认的做法。列表行要留这个位。
2. **音乐库页内的胶囊页签**（播放列表 / 收藏夹 / 合集 / 分p）——「分p」是 B 站
   独有的概念，这个页签结构本身就是 BBPlayer 的身份。
3. **同步状态用一个小图标 + 半句话**表达（`与 B 站「稍后再看」同步 ☁`）——
   不要写成一行说明文字。
4. **逐字歌词 / 桌面歌词 / 独立歌词窗口** —— BBPlayer 最强的差异点，桌面端
   已经有独立歌词窗口与 splash 解析，阶段 2/4 要让它在主界面也成立。
5. **装扮皮肤（`packages/core/src/theme`）在移动端是完整的资产体系**
   （skins / cards / playIcons / spaceBackgrounds …）。桌面端本轮**只做配色
   与材质**，但配色层要按"将来能接装扮"的方式留接口，不要把颜色写死在组件里。
6. **B 站曲目 / 网易云导入 / 合集 / 分p** 这些内容形态，决定了桌面端不能用
   一个纯"本地音乐播放器"的 IA 去套（Salt Player 是纯本地播放器）。

### 1.5 改造前截图里能看到的三个真实缺陷

1. **内容列与底部状态栏重叠**（`share-shots/08,10`）：`.main` 缺 `overflow:hidden`，
   而 `#view-share` 是 `#content` 的兄弟且没有自己的滚动容器 → 内容溢出
   `.app`（高度 `calc(100vh - 26px)`）压到状态栏上。
2. **左栏「同步」按钮被挤成两行**（"同 步"）——240px 分给「标题+首数+两个动作」不够。
3. **左栏标题截断**：`待分享歌单 mu5ww` 尾部数字被切掉。

## 2. 阶段划分

### 阶段 0 · 把「开发日志」清出主流程（先做，立竿见影）

按下面的审计清单逐条处理，并**新增一条探针断言**：主界面（除诊断页外）
的可见文本不得命中黑名单词。黑名单见 §4。

**顺带做掉的（原本排在阶段 1，但属于同一类"不像产品"的问题）：**

- **表单控件基础层**。原来的写法是给每个容器补样式
  （`.playbar button, .row-actions button, .search-box button`），而全工程有
  71 个按钮、18 个输入框、1 个 `select`、3 个滑块 —— 落在那些容器里的只是一部分，
  **其余全是浏览器默认样式**：设置页备份区那排灰按钮、原生下拉箭头、
  原生滑块（只设了 `accent-color`）、Chromium 的浅灰滚动条。
  现在改成「先给所有原生控件一个统一基线，容器只做微调」，
  并给按钮分了 filled / outlined / text 三档语义。
- **滑块自绘**。`appearance: none` 之后原生填充没了，所以轨道用
  `--range-fill`（JS 写入的百分比）分两段着色，三个滑块都要在设值后调一次
  `syncRangeFill` —— 漏一个就会显示成空轨道，这条有断言钉住。
- **诊断信息折叠区**。清掉的事实不能就此消失：凭据存储方式、WebDAV 密码
  存储方式、后端地址、数据目录都收进「设置 › 备份 › 诊断信息」，
  默认折叠，由设置套件断言「查得到」。
- **文案审计清单**里那些「显示绝对路径 / 显示 exportedAt」的项一并改掉：
  导出只说「已导出备份文件（1.6 MB）」+「打开所在文件夹」按钮；
  恢复成功只说「已恢复，重启应用后生效」+「立即重启应用」按钮。
