## 6.1 研究报告结论（两份只读代码分析，2026-09）

### A. 安卓端主页（`apps/mobile/src/app/(tabs)/index.tsx`，699 行）

**骨架**：固定头部（皮肤背景 + 问候栏 56px + 搜索栏）**不在滚动区内**；
下面一个 `Animated.ScrollView`，三个区块：

| #   | 区块                               | 形状                                                    | 依据                |
| --- | ---------------------------------- | ------------------------------------------------------- | ------------------- |
| 1   | **听歌频率热力图** `WeeklyHeatMap` | 全年 53 周 × 7 天，`cellSize=18 gap=4 r=4`              | `index.tsx:385-407` |
| 2   | 快捷入口（3 张卡）                 | 横滑，卡宽 140、圆图标 48 内 32px                       | `index.tsx:408-530` |
| 3   | **近期歌单**                       | 横滑，卡宽 140、封面 1:1、标题最多 2 行、副标题「N 首」 | `index.tsx:532-589` |

末尾 200px 留白（给悬浮播放条）；区块间距 `marginBottom:32`；
分区标题统一 `titleMedium + bold`（`index.tsx:646-650`）。
**区块本身不套卡片** —— 卡片化只发生在单个条目上（`colors.surfaceVariant` + `borderRadius:12`）。

**⚠️「近期歌单」有个最容易误抄的坑**：`useRecentPlaylists.ts:20-22` 实际查的是
`WHERE type != 'dynamic' ORDER BY updatedAt DESC LIMIT 6`，而
`playlists.updatedAt` 只在行被 `UPDATE` 时才动（`schema.ts:132-135` 的 Drizzle `$onUpdate`）；
**播放写的是 `play_history`，不碰 `playlists`**。
所以它是「**最近修改过的歌单**」，不是「最近播放过的歌单」。
桌面端必须二选一：改名「最近更新」，或新建播放历史表按播放时间排。

**热力图语义**（`packages/heatmap` + `hooks/queries/playHistory.ts:37-44`）：

- 数据 = `play_history` 按 `date(startTime/1000,'unixepoch','localtime')` 分组 `count()`
- 配色 = **主题 `primary` 的 20/40/60/100% 透明度**，空单元 `surfaceVariant`
- 档位是**固定阈值**（≥1 / ≥2 / ≥3 / ≥4 次），不是分位数（`calendar.ts:88-102`）
- 默认最近一年、初始滚到最新（`initialScrollEnd`）
- **每格可点** → `/history/YYYY-MM-DD`；有 `onMouseEnter/Leave` API 但主页没用
- 有数据/无数据都渲染网格（新用户看到全灰网格，不是空白）

**主页小按钮穷举**：`alert-circle`（仅同步失败时，→ 失败抽屉）／头像（→ 账号页）／
搜索栏清空。**主页没有"更多/设置"按钮** —— 设置是底部 tab。

**空状态**：主页**没有整页空状态**；「近期歌单」为 0 条时**整块不渲染**（连文案都没有）。

### B. 安卓端行操作 / 多选 / 批量添加

**行右侧是「⋮」而不是并排图标**，但点击后两类列表呈现不同：

| 列表                                             | 「⋮」打开                                              | 菜单项                                                                                  |
| ------------------------------------------------ | ------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| 收藏夹 / 合集 / 稍后再看 / 分P / up主 / 搜索结果 | 锚定的原生弹出菜单                                     | **4 项**：下一首播放、查看详细信息、添加到本地歌单、查看 up 主作品（**没有下载/删除**） |
| 本地歌单 / 动态歌单                              | `TrueSheet` 底部弹层（含当前曲目 header + 高频大图标） | 最多 7 项（另含缓存、复制封面、编辑信息、删除）                                         |
| 播放队列                                         | 无「⋮」                                                | **只有「×」移除**                                                                       |
| 分享歌单预览（只读）                             | 无任何按钮                                             | —                                                                                       |

**多选**：

- 进入：**长按行 500ms**（进多选并选中该行）；本地歌单还可从「⋮ → 排序」进入**不带选中**
  （把多选模式复用成了拖拽排序模式）
- 界面变化：Appbar 标题 → 「已选择 N 首」；**返回按钮被整组 action 替换**；
  行首复选框淡入 / 序号淡出；行右侧「⋮」消失（本地列表改出现拖拽把手）
- **没有底部操作条** —— 全部批量动作在顶部 Appbar
- 全选 / 反选在 Appbar；**没有"清空"也没有"退出"按钮**，只能靠系统返回
  （`useTrackSelection.ts:31-33` 的 `usePreventRemove`）——
  **这是移动端一个真实缺口**，桌面必须补
- 批量矩阵：收藏夹/合集/稍后再看/搜索/up主/分P = 全选/反选/**添加到歌单**；
  本地歌单 = 全选/反选/**删除**/添加到歌单；下载管理 = 全选/反选/批量删除/导出
- 批量删除**成功后退多选**；批量添加**不退**，且只 toast「添加成功」（信息量不够）

**「添加到歌单」弹层**：

- **是居中 Dialog，不是 bottom sheet**（`AnimatedModalOverlay` `justifyContent:center`，
  圆角 32，`maxHeight:85%`）—— 截图里偏下是手机长屏的错觉
- 结构：标题「添加到歌单」→ 歌单列表（`minHeight:300`）→ 脚注
  「与远程同步或订阅的共享歌单不会显示」→ 动作行（左「创建歌单」+ 右「取消/确认」）
- **单选 radio**；过滤条件 `type === 'local' && shareRole !== 'subscriber'`
  （即脚注的代码含义）；空态「你还没有创建任何歌单」；未选时确认禁用
- 写入：新歌**追加到末尾**；重复通过 `onConflictDoNothing` **静默忽略**
- **⚠️「创建歌单」有断点**：从本弹层点进去创建，成功后 `closeAll()` 关闭**所有**弹层，
  既不把选中的歌加进去、也不回到弹层 —— **用户白选一场**。桌面必须修
- 另有**单曲版**（`UpdateTrackLocalPlaylistsModal`）：checkbox 多选 + diff，
  **同时支持"加入"和"移出"**

**收藏夹详情右上角**：非多选态**一个按钮都没有**（只有左上返回）；
页面级操作全在列表头部卡片里 —— 主按钮「同步到本地 / 重新同步」，
已关联时多一个跳本地副本的圆按钮。

**本地歌单详情右上角**（才有）：同步失败告警（条件）／loading（条件）／
**搜索**（页内 DB 查询，切换 72px 搜索栏）／**「更多」**（7 项：播放器偏好、排序、
编辑信息、同步到 B 站、共享设置、置顶、删除）。
头部操作行：**播放全部** + 复制到本地歌单 + 下载全部。

**「同步到本地」是镜像语义**（`syncBilibiliPlaylist.ts:499-1049`）：
拉远端全量索引 → 查本地 → **算 diff 只拉新增** → `replacePlaylistAllTracks`
**全量重排**（顺序按 B 站收藏夹）。所以重复同步不会产生重复项，
**远端删掉的歌在本地也会消失**。收藏夹有 diff；**合集 / 多P 直接全量替换，没有 diff**。

**⚠️ 选中键必须用 `uniqueKey` 而不是 `track.id`**：
同一个 id 在搜索结果里是 `aid`、收藏夹里是 `bv2av(bvid)`、分P里是 `cid`、
本地是 DB trackId。跨列表使用会**串味**。

### C. 桌面端现状的一个关键事实

`renderer.js:236-237`：点「主页」执行的是 `bbHistory.show()` ——
**桌面的「主页」现在被播放历史页占用了，主页实际上不存在。**
复刻前必须先厘清这个占位。

⚠️ **提交前拦下一个正确性风险**：`AUTO_MATCH_THRESHOLD`（0.75→0.45）
**被桌面端外链歌单导入器共用**（`track-matcher.cjs:210`）。
两套打分函数不同却共用一个阈值，调一套会悄悄改另一套。
